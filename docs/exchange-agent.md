# Dream Poker Exchange

Telegram 환전방의 완료된 거래를 VND 현금, VND 계좌, KRW 계좌, USD 현금 원장에 기록합니다. 은행 이체나 실제 환전 지급을 실행하는 기능은 없습니다.

## 시작

전용 봇을 환전방에 추가한 다음 `.env.example`의 Exchange 환경변수와 `supabase/exchange_agent.sql`을 적용합니다. 봇 토큰과 웹훅 인증값은 다른 두 역할과 달라야 합니다. 담당 관리자의 숫자 Telegram ID와 타임존을 포함한 `EXCHANGE_ACTIVATED_AT`가 필요합니다.

관리자가 네 계정의 실제 기초 시제를 입력합니다. 없는 통화도 명시적으로 0을 적습니다. 외화의 동 기준 **총 취득원가**를 알면 함께 적고, 모르면 미확인으로 둡니다. 기본 환율로 과거 취득원가를 만들어 채우지 않습니다.

```text
기초 시제 동 현금 <VND>, 베트남 계좌 <VND>, 원화 계좌 <KRW>, 달러 현금 <USD>
```

봇이 미리보기를 반환하면 관리자가 제시된 `시제 확정 OPEN-<번호>`를 그대로 보냅니다. 미리보기는 30분 후 만료됩니다. 기초 시제 확인 전에는 거래를 원장에 기록하지 않습니다. 과거 채팅의 잔액을 현재 시제로 자동 사용하지 않습니다.

## 거래와 조회

아래는 사용 형식 예시이며 실제 처리된 거래가 아닙니다.

```text
베트남 계좌로 550만동 받고 현금 550만동 지급. 수수료 5만동은 계좌로 별도 받음
원화 계좌 30만원 입금, 18레이트로 동 현금 지급 완료
100USD 현금 받고 동 현금 250만동 지급 완료
베트남 계좌 수수료 수입 5만동, 별도 수수료 정산
시제
오늘 정산
이번 주 정산
지난주 정산
```

환율 기본값은 1 KRW = 18 VND, 1 USD = 25,000 VND입니다. 실제 지급액을 함께 적으면 이를 사용합니다. 수수료가 별도 수령인지 원금에 포함된 것인지 구분하며, 명시하지 않은 수수료를 차액에서 만들어 내지 않습니다.

`+50000`처럼 통화·방향·계정·분류가 없는 금액은 확인 질문을 돌려줍니다. 전달 메시지·수정 메시지·사진만 있는 요청도 자동으로 새 거래를 만들지 않습니다. 봇의 확인 질문에 답장하면 앞선 미완성 요청을 연결해서 해석합니다.

## 수익과 취소

- 원금 이동과 시제 보충·회수는 수익에 포함하지 않습니다.
- 별도 받은 수수료는 수익, 명시한 비용은 비용입니다.
- “환전수익 100만동”처럼 환전수익과 동 금액을 명확히 적으면 해당 금액을 통합 동 시제에 들어온 환전수익으로 기록합니다.
- 외화 매입 시 실제 지급한 VND를 취득원가에 더합니다. 외화를 처분할 때 가중평균 원가와 실제 VND 수령액의 차이를 실현손익으로 계산합니다.
- 원가를 모르는 외화는 전체 차익을 확정하지 않습니다. 보고서에는 원가 미확인 거래 및 보유 외화를 표시합니다.
- 보고 기간 시작이 원장 개시 이전이면 시작 잔액을 0으로 꾸미지 않고 `기록 전·미확인`으로 표시합니다.

관리자는 영수증의 거래 참조를 이용해 `FX-봇번호-업데이트번호 취소, 사유 …`를 요청할 수 있습니다. 취소는 원본을 지우는 대신 반대 분개를 추가합니다. 외화 취득원가에 영향을 주는 이후 거래가 있다면 가장 최근 거래부터 정리해야 합니다. 시제 보충·회수도 등록된 관리자만 요청할 수 있습니다.

## 중복과 운영 검증

Telegram 이벤트 키, 외부 거래번호, 답장 처리 관계를 DB에서 확인합니다. 방 단위 잠금·시제 버전·원자적 원장 반영으로 반복 요청과 동시에 들어온 거래를 제어합니다. 원장과 분개는 append-only이고 공개/일반 로그인 역할이 직접 읽거나 수정할 수 없습니다.

테스트는 정수 금액, 소수 USD, 수수료 포함/별도, 가중평균 원가, 미확인 원가, 기초 시제 확인, 원장 중복, 취소 순서, 이전 메시지·잘못된 방·역할 인증을 확인합니다. 운영 전에는 관리자 ID·실제 기초 시제·웹훅 전달을 확인해야 합니다. 마감 시 현금 실사와 은행 잔액을 장부와 대조합니다.
