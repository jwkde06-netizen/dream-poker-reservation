# Dream Buy-in Desk 개선 및 정산 시스템 선택

2026-10-21 운영 점검. 대상: Dream Staff 직원방, 일일 입력·플레이어 명단·F&B 입력, 기존 정산 봇.

## 권고

현재는 **구글 시트를 기준 장부로 유지하고 봇의 처리 정확도와 후속 처리를 먼저 안정화**한다. 이후 검증된 규칙과 데이터를 통합 프로그램으로 옮긴다. 직원에게 두 곳을 동시에 입력하게 하지 않는다. 이번 작업은 프로그램 이전을 실행하지 않는다.

핵심 문제는 시트 자체보다 게임 식별, 사진의 누적 칩 판독, 이전 답변 연결, 수동 수정과의 충돌이었다. 저장소만 바꾸면 이 문제는 그대로 남는다. 다만 프로그램은 고유 게임·선수 ID, 중복 방지 제약, 수정 이력과 동시 처리에서 장기적으로 유리하다.

## 관찰한 문제와 대응

| 문제 | 대응 | 남는 한계 |
|---|---|---|
| 인쇄 No.8과 실제 7번 게임 혼동 | 날짜·테이블에 한정된 번호 보정, 펜 표시 우선, 기존 세션 대조 | 날짜가 다른 게임까지 같은 보정을 재사용하면 안 됨 |
| 리바인 사진을 다음 게임으로 생성 | 누적 칩 수와 기존 게임 연결, 원본 메시지와 수동 번호 변경 연결 | 원본이나 직원 설명에 없는 사실은 알 수 없음 |
| Danny가 먼저 입력한 선수 중복 | 입력 직전 전체 장부 재조회 및 재계획, 기존 선수 행 재사용 | 시트에서 사람이 최종 확인과 쓰기 사이에 수정하는 극히 짧은 경쟁 구간은 남음 |
| 취소한 선수가 다른 게임에 참가 | 취소는 해당 날짜·세션에만 적용, 다른 게임 참석은 별도 처리 | 같은 게임에서 취소 후 복귀가 모호하면 해당 선수만 질문 |
| 이름 띄어쓰기 때문에 반복 질문 | 마스터 표기 정규화와 승인된 별칭 사용 | 서로 다른 영문 이름은 임의 합치지 않음 |
| 신규 선수 기본 코드 답변이 등록에서 멈춤 | 명시된 신규 선수에 승인된 기본 KOREA 적용, 특정 세션 착석까지 연결 | 기존 HOUSE·UK·KOREA2 코드를 바꾸지 않음 |
| 손영호→손열호 수정으로 재제출 요구 | 영문명·게임·금액이 동일한 짧은 한글 이름 오타 수정은 재처리하지 않음 | 금액·게임·영문명 변경은 단순 오타로 간주하지 않음 |
| 기울어진 사진에서 오른쪽 금액 행을 잘못 연결 | 기존 게임 종이 사진은 이름 열과 칩 금액 열을 별도로 다시 읽고 선수별 비교 | 두 판독이 함께 틀릴 가능성은 남음. 일치하지 않으면 해당 선수만 보류 |
| 반영했지만 완료 답글 누락 | 저장·재조회 확인 후 완료 ✅, 저장된 답글 재전송 경로 유지 | Telegram 전송과 DB 기록은 하나의 원자적 작업이 아님 |
| 어느 요청이 막혔는지 불명확 | 정산상태 명령, 처리 시간·AI 호출·토큰 기록 | 과거 기록에는 시간·토큰이 없어 이전 성능 수치를 만들 수 없음 |

## 세 가지 선택 비교

| 기준 | 시트 직접 입력 | 시트 + 개선된 봇 (현재 권고) | 전용 통합 프로그램 |
|---|---|---|---|
| 직원 입력 | 사람이 모두 작성 | 사진·짧은 글, 애매한 항목만 확인 | 같은 입력 방식 + 전용 수정 화면 |
| 즉시 수정 | 익숙하고 빠름 | 기존 시트 수정 가능, 다음 처리 시 감지 | 수정·취소·복귀 기능을 먼저 구현해야 함 |
| 동시 작업 | 셀 충돌 가능 | 봇 작업 직렬화·쓰기 전 재확인 | DB 트랜잭션·고유 제약으로 더 강하게 제어 가능 |
| 게임 정체성 | 행 위치와 표기 의존 | 세션·날짜·원본 사진을 함께 추적 | 변경되지 않는 game_id와 player_id 사용 가능 |
| 오류 검토 | 사진과 시트를 사람이 대조 | 확인 대기 목록과 원본 연결 | 원본·입력 전후·담당자·취소 이력을 한 화면에 제공 가능 |
| 정산 공식 | 기존 공식 즉시 활용 | 공식 열을 보호하면서 입력 | 공식을 코드로 옮기고 동일 결과를 검증해야 함 |
| 장애 대응 | 직접 입력 지속 | 봇 장애 때 직접 입력 가능 | 백업·복구·수동 대체 입력이 준비되어야 함 |
| 도입 부담 | 낮음 | 현재 연결·인증 재사용 | 개발·교육·데이터 이전·대조 비용 발생 |
| 장기 확장 | 복잡해질수록 관리 부담 | 단기 효율 개선에 적합 | 다점포·권한·마감·통합 보고에 적합 |

## 비용 판단

실제 계정 청구 금액과 직원 처리 시간을 아직 충분히 측정하지 않았으므로 월 총비용이나 절감률을 확정하지 않는다. 봇의 AI·서버 비용은 시트와 프로그램 어느 쪽에서도 발생한다. 전용 프로그램의 가장 큰 추가 비용은 초기 개발과 이후 유지보수다.

Google Sheets API의 표준 사용은 현재 추가 요금이 없지만 분당 요청 한도가 있으며, 공식 문서는 2026년 후반 한도 초과 사용에 대한 과금 계획도 안내한다. Supabase Pro 공개 요금은 월 US$25부터이며, 이것은 전체 솔루션 비용이 아니다. 현재 사용 중인 프로젝트의 요금제와 추가 사용료는 별도 확인이 필요하다. 기존 인프라를 재사용하고, 반복 확인이 필요한 사진에만 추가 판독을 수행한다.

비교 지표: 월 도구비 + (직원 입력·확인·재작업 분 × 실제 인건비) + 장애 대응·유지보수 시간. 단순 자동 처리 비율보다 직원의 실제 손이 가는 시간을 우선한다.

## 전환 조건 — 아직 달성했다고 주장하지 않는 목표

1. 최소 7영업일·100건 이상의 검증된 실제 요청에서 잘못된 게임 반영·중복 입력 0건.
2. 명확한 표준 사진의 추가 질문 없는 처리율 95% 이상. 불명확 사진은 별도 집계.
3. 처리 완료까지 p95 60초 이내를 목표로 측정. 현재 새 측정 기록을 쌓는 단계.
4. 매일 선수별 바이인·코드별 금액·F&B 총액을 직원 마감 결과와 대조.
5. 담당자가 오류를 1분 내 수정할 수 있고, 수정 이력과 원본을 확인할 수 있음.
6. 백업에서 복구하고 시트로 내보내는 절차까지 검증.

조건을 충족하면 전용 프로그램을 읽기 전용 검증 모드로 먼저 운영한다. 이때 시트가 유일한 기준 장부다. 결과가 일치하고 직원 수정 화면이 준비되면 정해진 마감 시점을 기준으로 DB를 유일한 기준 장부로 전환한다. 이후 시트는 자동 출력·보고용으로 사용하며 양쪽에서 동시에 원본을 수정하지 않는다.

## 전용 프로그램에 필요한 최소 기능

- 고정 game_id/player_id, 날짜·전체 게임 순서·테이블 회차를 별도 필드로 관리.
- 입장·리바인·취소·복귀를 원본 메시지와 연결된 이력으로 저장. 취소 시 다른 게임 이력 유지.
- 동일 메시지 재전달과 동일 선수·세션 중복 방지.
- 직원 수정 전후 값·담당자·시각 기록, 충돌 시 최신 값 기준 재검토.
- 확인 대기 목록, 재처리, 완료 답글 전송 상태 표시.
- 기존 코드별 공식과 F&B 집계의 동등성 검증, 일일 마감 후 수정 승인, 주간 월~일 보고.
- 기존 시트 형식 내보내기, 최소 권한, 백업·복구.

- 새로운 시간·토큰 측정은 배포 이후 요청부터 쌓인다. 장기 무오류나 95% 자동화 달성을 아직 입증하지 않았다.
